# 深圳职业技术大学《学生手册》智能问答

## 一、解决的核心问题

《学生手册（2025 年修订）》正文将近 4 MB、974 个条款。学生想问「挂科怎么办」
「补考成绩怎么算」，翻 PDF 又慢又容易找漏。

直接问通用大模型呢？它会**编**——把不存在的条例说得像真的一样。手册这类内容，
答错一条就是误导学生。

所以本项目只解决一件事：

> 答案**只从手册原文里来**，每条结论都能点回它引用的那一条；手册里没写的，
> 明说「本手册中没有对应内容」，绝不臆测。

## 二、技术栈

**界面与服务**
- Streamlit 单页应用（入口 `app.py`），无侧边栏，手机/电脑都能打开

**大模型（负责组织语言）**
- 智谱 GLM-4-Flash（免费档，默认）；接口是 OpenAI 兼容格式，可换 DeepSeek 等
- 用 LangChain（LCEL）编排调用；撞上游限速会自动重试

**检索（负责把问题对上手册条款）**
- 向量检索：`BAAI/bge-m3`（1024 维），语义相近就能命中
- 关键词检索：自研 BM25（字符 bigram），专治「问法和原文用词不一样」
- 两路结果用 RRF 融合，再用 `BAAI/bge-reranker-v2-m3` 重排精选
- 编码与重排有两种跑法，配置切换即可：**本机显卡**（sentence-transformers）或
  **在线接口**（硅基流动 / 模力方舟，给没有显卡的线上环境用）

**数据**
- 手册 PDF → 974 个条款 → 1510 个检索块（每块记住它属于哪条、原 PDF 第几页）
- 向量**离线算好一次**存进 `data/`，随仓库分发，运行时不再重算

**自研校正层（本项目的重点，不靠模型自觉）**
- 引用校验：逐条核对答案里的 `[E1]` 角标与原文，对不上就降级或拒答
- 拒答复核：模型说「证据不足」但检索分其实够高时，判为误拒并让它重答
- 口语词映射：把「体测 / 挂科 / 打小抄」换成正名再检索
- 程序化兜底：大模型不可用时，改成照抄手册原文作答，并在页面上明说

**存储**
- 本地：访问日志、运行日志
- 云库（Postgres + PostgREST）：留言墙、使用统计、匿名会话记忆

## 三、运行流程

```
学生提问
   │
   ① 规划      判断要不要拆成几个小问题；把口语词换成正名     ← 大模型 + 口语词表
   │
   ② 检索      向量（bge-m3）与关键词（BM25）两路并行
   │           → RRF 融合 → 重排精选（bge-reranker-v2-m3）
   │
   ③ 生成      只拿检索到的原文条款作答，每句都标 [E1] 出处   ← 大模型
   │
   ④ 自检      证据不够就再检索一轮
   │
   ⑤ 校验      逐条核对角标与原文（自研，不靠模型自觉）
   │           判「证据不足」但检索分够高 → 认定是误拒，带纠正提示重答
   │
   ⑥ 出答案    可点击角标 → 跳到该条手册原文；另附「内部过程」面板
               （大模型不可用 → 走程序化兜底，照抄原文并明说「本次是兜底」）
```

跑起来（在项目根目录）：

```
pip install -r requirements-local.txt     # 本机跑用这份；线上用 requirements.txt
# 在项目根建 .env（可参考 .env.example），填上密钥
双击「启动网页问答.bat」                    # 或 python -m streamlit run app.py
```
